Exercises — 5. Hybrid systems: Hybrid equations

Draft for a 90-minute TA-supervised session. Designed to plug into the placeholder at https://hurak.github.io/hys/5_hybrid_equations/exercises.html.

Targets both skill-level learning goals of this chapter: - Find a model of a dynamical system in the form of hybrid equations (determine {f, C, g, D}). - Implement a model in the form of hybrid equations using the HyEQ Toolbox.

Session plan (90 min total)

Time Block
0–5 min Framing: why asynchronous sampling and supervisory switching both need the hybrid-equations formalism
5–50 min Exercise 1 — event-triggered PID (hands-on, pairs, TA circulates)
50–55 min Break / transition
55–70 min Exercise 2, Part A — instructor-led demo (pendulum swing-up + LQR supervisor)
70–88 min Exercise 2, Part B — guided exploration/extension (pairs, TA circulates)
88–90 min Wrap-up, collect deliverables

Exercise 1: An event-triggered PID controller as a hybrid system (≈45 min)

Goal: practice formulating a sampled-data control loop with non-periodic, event-triggered sampling as a hybrid equation {f, C, g, D}, and implement/simulate it with the HyEQ Toolbox.

Background (hand out to students)

Recall Example 5 in the lecture notes: a sampled-data loop with periodic sampling is written as a hybrid system with state x = (x_p, u, τ), flow set C = {τ ∈ [0,T)}, and jump set D = {τ ≥ T}. The controller output is only recomputed at the jumps.

An event-triggered (a.k.a. send-on-delta or Lebesgue) controller replaces “recompute every T seconds” with “recompute only when the output has drifted enough to matter.” This is the idea behind Årzén’s 1999 event-based PID controller: a comparator continuously watches the plant output and triggers a recomputation only when it has changed by more than a threshold Δ since the last update, cutting CPU/network load with little performance loss (Årzén, A Simple Event-Based PID Controller, 14th IFAC World Congress, 1999 — tested on a double-tank process). The hybrid-equations framework is exactly what lets you formalize “sample now, or don’t” without treating it as a separate discrete-event layer bolted onto the ODE.

Plant given to students

A simple second-order plant with an integrator and damping (good match for PI action):

ẋ_p1 = x_p2
ẋ_p2 = -x_p2 + u
y    = x_p1

(Optional stretch: swap in Årzén’s nonlinear double-tank model if a pair finishes early — two coupled tank levels, ẋ1 = -k1√x1 + u, ẋ2 = k1√x1 - k2√x2, y = x2.)

Controller structure

A PI controller, but written to use the hybrid framework’s own bookkeeping: the integral term accumulates using the actual elapsed flow time τ recorded since the last event (rather than assuming a fixed T), and only u is held between events.

State vector (some entries intentionally left for students to justify)

x = (x_p, u, z, τ, y_last) where z is the running integral term, τ is the timer since the last event, y_last is the output value recorded at the last event, and τ_min is a small minimum dwell time (a design parameter, not a state).

Tasks

(a) [~5 min] Orient. By analogy with Example 5, list which of the four components {f, C, g, D} must change to go from periodic to event-triggered sampling, and which stay the same.

(b) [~15 min] Derive the model. Given

f(x) = ( x_p2, -x_p2 + u,  0,  0,  1,  0 )
  • Write the flow set C: flow continues while either the minimum dwell time hasn’t elapsed, or the output hasn’t drifted by Δ from y_last.
  • Write the jump set D as its complement.
  • Write the jump map g: derive the expressions for e, z⁺ (integral update using the elapsed τ), u⁺ = Kp·e + z⁺, τ⁺, and y_last⁺.

(TA hint sheet, not for students: C = {τ ≤ τ_min} ∪ {τ > τ_min ∧ |y − y_last| < Δ}; D = complement; z⁺ = z + Ki·e·τ.)

(c) [~20 min] Implement and simulate. Using the HyEQ Toolbox skeleton (TA-provided .slx with plant wired and empty f/C/g/D MATLAB Function blocks — see logistics below), simulate a unit step reference. Suggested parameters: Kp = 2, Ki = 1, Δ = 0.05, τ_min = 0.01 s, horizon 10 s. Plot y(t) and u(t) with event instants marked (stem plot), and count the number of controller updates.

(d) [~5 min] Compare and discuss. Compare the event count against a periodic PID sampled at a rate giving comparable tracking error. What happens as Δ → 0? As τ_min → 0? Did you observe very rapid, closely spaced triggering near the target (a preview of the Zeno phenomenon, covered formally in Ch. 7)?

Deliverable: the filled-in {f, C, g, D}, the Simulink/HyEQ model or script, one annotated plot, 3–4 sentences answering (d).

Optional stretch (if a pair finishes early): add a derivative term computed from the two most recent event samples; or swap in the double-tank plant; or add a “watchdog” periodic fallback update (as later event-based PID papers do) to bound the maximum inter-event time from above as well as below.

Exercise 2: Supervisory switching between a local and a global pendulum controller (≈30–35 min)

As you noted, deriving a swing-up (energy-shaping) controller and computing a region of attraction from scratch draws on competences outside this course. So this exercise is split: the control laws and the ROA are given, and the exercise itself is scoped tightly to what this chapter is teaching — encoding a hysteresis-switched supervisor as {f, C, g, D}, directly extending Example 7 (stabilization on a circle), which students will already have worked through minutes earlier.

Part A — Instructor-led demo (~15 min)

Walk through a fully worked solution, presented explicitly as an instance of Fig. 9–11 (supervisory control / combining local and global controllers) in the notes:

  • Pendulum, state x = (θ, θ̇), upright equilibrium at θ = 0.
  • Local controller (κ_loc): LQR on the linearization about θ = 0. Region of validity estimated as a sublevel set of the LQR Lyapunov function, {x : V(x) ≤ c}, V(x) = xᵀPx. Give students P and c as precomputed numbers — explain what a Lyapunov sublevel set buys you (an invariant, attractive region) without deriving how c was found.
  • Global controller (κ_glob): an energy-shaping swing-up law, e.g. u = k·θ̇·cos(θ)·(E(x) − E_top). Present the formula and the one-line intuition (pump energy in until total energy matches the energy at the upright point), not a stability proof.
  • Supervisor: discrete state q ∈ {0,1} (0 = global/swing-up, 1 = local/LQR), switching with hysteresis — exactly the c₀/c₁ pattern from Example 7:
    • switch global → local when V(x) ≤ c_in,
    • switch local → global only if V(x) ≥ c_out > c_in.
  • Show a live simulation (HyEQ Toolbox, or the Julia OrdinaryDiffEq + DiscreteCallback pattern already used for Example 7 in the notes) of a full swing-up-and-balance run.

Part B — Guided exploration (students, TA-supervised, ~15–20 min)

Students do not re-derive the controllers or the ROA. Their task is the hybrid-equations-specific part, using the demo code as a given starting point.

(b1) [~5–8 min, everyone] Write the model. Using κ_loc, κ_glob, V, c_in, c_out as given black-box quantities, write out {f, C, g, D} for the supervisory system in the same notation as Fig. 11 / Example 7 (a fill-in-the-blanks worksheet works well here — this is the direct “find a model” exercise for this chapter’s learning goal, just with the plant now nonlinear and the sets defined via V(x) rather than a scalar coordinate).

(b2) [~5 min, everyone] Break the hysteresis. In the provided code, set c_in = c_out = c (no hysteresis gap) and rerun. Report what happens near the boundary of {V(x) = c} — this should reproduce, in a new setting, the “hysteresis is a robustifying feature” point made in the notes.

(b3) [~10 min, pick one per pair] Extension menu: - Add torque saturation to both controllers and adjust c_in/c_out so switching only happens where the saturated global controller is still not needed/local controller is still valid. - Try two different initial conditions (near the bottom vs. off to one side) and report time-to-upright and number of switches for each. - Replace the hysteresis rule with a minimum-dwell-time rule (structurally identical to τ_min from Exercise 1) instead of a geometric margin, and compare switching behavior with a bit of noise added to the θ̇ measurement. - (Bonus, optional) empirically tighten the given ROA estimate: grid a few candidate values of c and check whether trajectories started on {V(x) = c} under κ_loc alone stay inside the region and converge.

Deliverable: the annotated {f, C, g, D}, one plot showing the effect of the chosen extension, 2–3 sentences of interpretation.

Logistics notes for the TA

  • Toolchain: the course page recommends the HyEQ Toolbox beta (v3.1.0.04) for Matlab/Simulink. Confirm it’s installed on lab machines before the session — this exercise assumes zero install time in-class. If Simulink access is unreliable, the Julia OrdinaryDiffEq + DiscreteCallback style already used for Example 7 in the notes is a lighter-weight fallback and keeps the same C/D/g structure.
  • Skeletons, not blank canvases: for both exercises, pre-wire the plant, solver harness, and plotting, and leave only f, C, g, D (and, in Ex. 1, the controller gains) as blanks. 45 and 30 minutes are not enough to build a Simulink model from scratch and reason about the sets.
  • Common beginner bug to watch for: boundary handling between C and D — strict vs. non-strict inequalities at the same boundary can cause chattering or solver deadlock. This is worth flagging explicitly, since Exercise 1(d) and Exercise 2(b2) are designed to make students see this happen rather than just be warned about it.
  • Grading signal, not just a plot: the useful checkpoint for both exercises is the written {f, C, g, D}, not just a working simulation — a student can sometimes get a plausible-looking simulation from a wrong or incomplete model.
